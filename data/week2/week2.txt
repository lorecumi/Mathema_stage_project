1. Creazione di una prima API Django

Partendo dal progetto Django che hai già sperimentato, crea un'applicazione chiamata, ad esempio, records, e installa Django REST Framework.

Come primo esercizio, crea un endpoint:

POST /api/records/ – riceve un singolo oggetto JSON nel formato canonico e lo restituisce come risposta.

Per ora non è necessario salvare nulla nel database. L'obiettivo è capire come Django riceve una richiesta HTTP POST, legge il JSON e restituisce una risposta.

Puoi iniziare testando l'endpoint manualmente con un record preso da canonical_example.json.

Tutorial: https://www.django-rest-framework.org/tutorial/1-serialization/

2. Validazione dei dati ricevuti

Una volta funzionante l'endpoint, aggiungi una semplice validazione utilizzando i serializers di Django REST Framework.

Inizia verificando la presenza dei campi obbligatori, almeno id e title. Se mancano, l'API deve restituire un errore HTTP 400 con un messaggio comprensibile.

Risultato atteso: Django riceve un JSON, verifica i campi principali e restituisce una risposta corretta o un messaggio di errore.

3. Introduzione al database e a JSONField

Ora puoi creare un modello Django chiamato HeritageRecord, che permetta di salvare:

l'identificativo univoco del record;

il titolo;

il record canonico completo attraverso un campo JSONField.

JSONField permette di conservare un oggetto JSON nel database mantenendo la sua struttura, comprese le proprietà annidate e le liste. In questo modo non dobbiamo creare subito una colonna per ogni campo del canonical model.

Per iniziare puoi utilizzare SQLite, già supportato da Django.

Crea le migrazioni e modifica l'endpoint POST affinché salvi il record ricevuto nel database, evitando l'inserimento di ID duplicati.

Tutorial: https://docs.djangoproject.com/en/6.0/ref/models/fields/#jsonfield

4. Recupero dei dati salvati

Aggiungi due endpoint:

GET /api/records/ – restituisce tutti i record salvati;

GET /api/records/{id}/ – restituisce il record con l'identificativo richiesto.

Verifica anche che i dati rimangano disponibili dopo aver riavviato il server Django.

5. Collegamento tra FastAPI e Django

A questo punto puoi riprendere il progetto della prima settimana.

Attualmente FastAPI legge i file CSV/JSON e li trasforma nel canonical model. Vorrei che provassi a collegarlo alle API Django, in modo da inviare i record trasformati tramite richieste HTTP POST e salvarli nel database.

Puoi utilizzare la libreria Python requests per effettuare le chiamate HTTP.

Per questa prima versione è sufficiente che il trasferimento avvenga tramite uno script o una funzione dedicata. Non è ancora necessario implementare l'upload dei file attraverso un'interfaccia.

Risultato atteso: leggere un file con FastAPI, trasformare i record, inviarli a Django e ritrovarli nel database.
